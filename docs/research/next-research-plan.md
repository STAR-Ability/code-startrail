# 下一轮研究与低成本验证计划

日期：2026-09-27。目标：区分“培训组织问题”“普通AI可以解决的问题”和“专门训练流程能增益的问题”。当前78份问卷只是形成假设的输入，不预设产品成立。

## 1. 首先修复本轮测量盲点

向问卷维护者核对Q5/Q18是否最多选5项、Q13–17正式跳题规则、Q19是否可选未入围功能及投放范围。不联系或追踪匿名答卷中的具体学生。下一轮另开自愿招募入口，不把问卷中的试用意愿当作联系许可。

补采邀请人数、应答人数与招募渠道；可收宽泛学习阶段/课程班次，用于描述覆盖，不收可回溯个人的组合。若课程改动或样本构成变化，分别报告，不强行与本轮合并。

新问卷必须允许“没发生”“不适用”“不愿回答”；“没有问题/不记录”与其他选项互斥。AI行为设置明确时间窗，如“过去7天”；先问是否真的使用，再跳题。功能优先题应展示已选项并允许回到上题修订，记录确认后的选择。说明次数限制，避免误将竞争性选择当无需求。

## 2. 三个优先产品假设

| 假设 | 当前依据 | 低成本实验 | 反证/停做信号 |
| --- | --- | --- | --- |
| H1：规则匹配的分级小题单能减少无效卡住 | 推荐57/78，但不知道刷什么仅11/78；可能是难度/路线匹配诉求 | 两组经教练审定的小题单，按基础平衡随机分配；比较实际开始、过易/过难、有效完成及迁移，内容量相同 | 通用入门题单表现相同且更易维护，或诊断成本高于收益；只保留人工题单 |
| H2：提问式引导改善独立迁移 | 53/78题解懂但写不出；16/78把提问引导列唯一优先 | 固定教练提示、普通AI＋学习提示词、受控Agent三条件；控制题难度、时间和可用资源 | 没有实质迁移增益，频繁使学生沮丧/弃做，或收益全由更多练习时间解释 |
| H3：明确错误原因＋相近复测降低同类错误 | 39/78不知卡点、27/71 AI后未掌握；愿记错误主题65/78 | 错误修复后按参与者随机：标准反馈 vs 错误标签/解释＋匹配复测；等量练习和时间 | 加重记录负担、标签不准确、保持/重复率不优于等量普通练习 |

H1/H2/H3不要求在一个小样本里同时给出确定结论。Phase 0优先发现不可行处；一次只改变一个关键条件，避免完整闭环有效却不知哪部分有效。

## 3. 访谈与观察：找具体事件

招募8–12名新生，覆盖尚未接触、语法入门、数组及以上，包含AI使用较多/较少者以及愿试用/犹豫者；目标是多样案例，不是按小组算统计显著。教练/学长另访谈3–5人。招募时重新询问这些宽泛条件，不能用匿名问卷猜测身份。

每次约25–35分钟，愿意时带一份最近训练记录，不强制导出完整AI历史。先复述真实事件，再展示想法，避免一开始介绍Agent诱导回答。

1. 最近一道卡住的题：题意、尝试、卡了多久、在哪一步停止，最后怎么继续？“不会”具体指哪种动作？
2. 最近一次看懂但写不出：关掉题解能写到哪里？是忘了性质、缺语法、不会组织代码，还是题解未读懂？
3. 最近一次没问出口：当时想问谁、为什么没问、后续怎样？提供问题模板是否真的有帮助？
4. 最近一次问AI：原问题怎样描述，是否看了完整解法，怎样验证，隔天能否做相近题？只看自愿分享的片段。
5. “按水平推荐题目”到底期望什么：更简单、更多前置解释、循序题单、了解入队标准，还是减少搜索时间？
6. 普通AI已经足够的地方有哪些？什么情况下宁愿用题解、学长、同学而不使用新系统？
7. 让用户实际选：一句提示、一个诊断问题、完整讲解；选择之后观察完成任务，而非只询问偏好。
8. 记录错误主题、代码片段、完整对话分别愿不愿意；保存多久、谁能看、如何删除才清楚？不接受也能参加吗？
9. 哪一件培训改动能立即帮忙：分层、作业讲评、课内练习、预习、进度、自主在线学习？组织能否先做？

教练访谈重点：哪些初学错误最常见、怎样判断独立掌握、哪些提示会泄露关键答案、有哪些已验证题组、数据是否真的改变下一次教学决策。不要用学生对看板的低票推断教练没有需求。

## 4. Phase 0：先做流程与测量可行性

12–18名自愿参与者，持续约2周，不能据此声称有效性已被统计验证。先用人工题单、固定提示与人工Debug核验，记录时间/成本，了解“复测”能否实际完成。

让所有条件共享基础教学改进，或单独记录改动日期；不把讲慢了、增加讲评后的进步算作Agent效果。安排一次普通AI对照的真实任务，允许退出，观察为什么拒绝提问式交互。

可行性通过条件是测量可执行：参加者能理解操作，计划中的事件和核验结果可连成一条链，完成任务和缺失原因可区分，提示泄露抽查可复核，至少完成两轮小规模观察。门槛先写定，遇到隐私泄露、运行不安全或门控失效先修复。

## 5. H2学习效果实验：强对照、等价题与无辅助终点

优先做三条件随机交叉可行性实验，每名学生在不同但相当知识点/难度的题组上体验：A普通AI＋明确“不直接给答案”的学习提示词；B教练事先编写的逐级提示（无需LLM）；C完整Agent流程。各条件获得相同题面与背景信息、相同练习时长和测验机会。

使用ABC、ACB、BAC、BCA、CAB、CBA六种顺序平衡分配，并将知识点/题组轮转，不能同一人反复做同一题。12–18人可用六种顺序做2–3次重复，只用于流程估计。匹配题由不知道分组的教练先审定并小规模试做，避免C组更简单。

每次训练后做一题同知识点但未看过的迁移题；关闭AI、题解和真人帮助，记录实际可用资源。训练过程中是否解锁答案不改变原分配组归属；答案暴露作为过程指标与次要分层，不能把失败者排出主要分析。48–72小时后做另一道保持题，窗口仅为初始研究安排，不是假设统一遗忘周期。

评分者看匿名代码/作答及测试结果，不看组别；先冻结评分标准：通过规定测试、核心性质解释、独立实现所需关键步骤。原题AC不替代迁移，学生自报“我懂了”也不替代盲评。

交叉设计仍有学习携带效应，不能靠短暂“洗脱”消除知识。记录顺序、题组与阶段；分析每人每条件汇总，做参与者层级的配对/置换或聚类bootstrap区间，不把同一学生多道题当成独立样本。若明显跨条件学习或频繁分享题解，正式试验改为参与者平行分组，并重新估计样本量。

**主要终点**：所有预定无辅助迁移任务中成功比例，按初始分配分析，未完成/未出现主要口径记为未成功，另报完成者口径与缺失原因，并做最好/最坏情形敏感性。技术故障预先规定补测与排除规则，不在看过结果后改变。选择一个主要比较（C vs A）；C vs B及保持/成本等标为次要，限制比较数量并预先规定多重处理。

可参考的最小有价值差异为10个百分点，**这是管理选择，不是本问卷估计**。正式试验样本量需先估基线、题组差异、个体内相关与失访。示例：假设独立两组从50%提高至60%，双侧α=0.05、80%把握度，简单正态近似约需387人/组，尚未加失访或集群效应；不能拿几十人的无显著结果证明无效。交叉设计可能需要更少，但必须依据先导数据模拟，不能套用该387人数字。

报告实际绝对差、区间、原始人数/分母和成本。效果方向不明确时应补数据或缩小主张；不能以满意度高、点估计过线或探索性p值小为理由直接推广。

## 6. H1与H3的低成本变体

H1：在相同知识目标和时间预算下，对比人工通用入门题单与短诊断后的规则匹配题单。记录“题目太难/太易”的具体依据，检查推荐是不是只把题换得更简单。主看合适任务的完成与后续迁移，不能只看开始率。

H3：把“记录错误标签”与“多做一道复测题”的作用区分。两组均有相同练习量，一组收到标准反馈，另一组增加经确认的错误解释/标签并匹配练习；明确机会数后比较同类错误。如果预算足够再单独测试练习间隔，不在第一轮同时测试复杂记忆调度。

## 7. 下一轮问卷补充问题

| 要补的内容 | 建议问法/任务 | 用途 |
| --- | --- | --- |
| 真实训练基线 | 过去7天练了几次、完成/未完成哪类题；可自愿关联匿名训练日志 | 统一时间窗口，识别意愿与行为落差 |
| AI验证方式 | 是否跑样例、构造边界/反例、独立推导、对照可靠资料；现场验证一个错误答案 | 区分“说会验证”和“会验证” |
| 完整代码暴露 | 最近一次在什么阶段看到完整解法，之后怎样重做 | 校正社会赞许偏差，不批判性追问 |
| 卡题位置 | 题意、性质、语法、实现、反例、复杂度；用一题任务定位 | 避免一句“不会算法”包办所有原因 |
| 掌握/保持 | 无辅助迁移题、隔天同类题、实际错误类型 | 衡量能力而非过题 |
| 中断与负担 | 什么时候停止，为什么；提示过长/追问太多/时间安排/难度 | 判断产品是否反而打断训练 |
| 题单偏好根因 | 同目标下实际选更简题、更多解释、阶段计划、入队标准；再追问原因 | 分清推荐功能背后的诉求 |
| 授课与组织 | 当前前置知识、讲练比例、讲评与可用学习时段 | 找可先做的非AI改进 |
| 数据边界 | 错误标签/代码/对话分别选择，拒绝也可使用；理解检查 | 用明确授权替代笼统意愿 |
| 持续使用与替代 | 一周后实际是否回用，没用时用了什么；不先问“是不是很好用” | 解释留存，识别普通AI足够的场景 |

## 8. 事件字典与最小采集

共同字段：随机participant_id、session_id、problem_id与版本、condition、时间、事件schema版本、题目难度/知识点、核验来源。研究导出删除精确时间和身份联系方式，按日/时长分档；并保留随机化日志和分析代码在受控位置。

| 事件 | 必要附加字段 | 不应混淆 |
| --- | --- | --- |
| session_started / paused / resumed / ended | 进入方式、有效任务时长、退出原因 | 在线时长不等于学习时长 |
| help_requested / hint_shown | 用户请求、提示层级、题/提示/模型版本 | 点击不等于读懂 |
| full_explanation_requested / shown | 明确请求时间、是否提前泄露人工标记 | 已请求与未请求泄露分开 |
| attempt_submitted / verified | CE/WA/AC等、核验来源、反例是否可复现 | 自报AC不当作核验AC |
| error_confirmed | 原因标签、用户/教练确认、可选证据引用 | AI猜测不当作根因事实 |
| transfer_assigned / completed / scored | 是否无辅助、盲评分、未参加原因、延迟窗口 | 完成者与全部分配任务分别报告 |
| consent_changed / deletion_requested | 分项范围、版本、完成删除状态 | 研究参与同意与产品数据授权分开 |

默认不采完整AI历史、IP/设备指纹、社交账号。只对愿意且解释清楚的个案收代码片段/对话片段，删除姓名注释。学生随时退出，不影响教学资源；原问卷匿名性不应因招募被破坏。

## 9. 分析与交付清单

试验前冻结假设、主要终点、最小有价值差异、随机化、题组/评分标准、缺失与技术故障规则、样本量和停止条件。先锁定分析，再解盲结果。报告参与流程图、分配/退出/完成数量，按用户而不是按聊天条数计算样本量。

试验后输出：去标识事件表、题组与评分版本、每人每条件汇总、主要比较效应和区间、失访/故障敏感性、成本、伤害/挫败案例和反例。开放访谈主题由第二位分析者复核一部分，保存分歧与修改，不只保留支持产品的发言。

成功条件以学习增益、持续使用和可承担成本共同判断；若固定题单/提示足够，保留简单方案。只有本校多轮结果可重复后才邀请其他学校，逐校报告外部有效性。付费、教练接入、跨校适配和长期价值另设研究，不由当前78份问卷代推。
