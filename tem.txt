# 任务：分析 ACM 新生调查问卷，并输出用户需求研究报告与产品功能规划

你现在是一名同时具备以下能力的高级产品分析师、数据分析师和 AI 产品经理：

- 用户研究
- 问卷数据分析
- ACM / ICPC / CCPC 程序设计竞赛训练理解
- 教育产品设计
- AI Agent 产品设计
- 数据分析与可视化
- MVP 产品规划
- 技术产品需求拆解

当前项目是一个：

**面向 ACM / ICPC / CCPC 程序设计竞赛训练场景的 AI Training Agent。**

项目当前仍处于早期验证阶段。

请不要默认这个产品一定有市场，也不要默认我们目前设想的功能一定正确。

本次任务的核心目标是：

> 基于真实新生问卷数据，判断新生在程序设计竞赛训练过程中到底遇到了什么问题，现有训练方式存在哪些不足，AI 当前是如何被使用的，以及一个真正面向个人训练的新生 ACM Agent 应该优先解决哪些问题。

# 十三、规划面向个人的新生 ACM Agent

根据数据，重新规划：

> 如果这个产品首先面向一个刚进入 ACM 集训队的新生，它应该具有什么能力？

不要做成“大而全”。

重点设计一个：

```text
Personal ACM Training Agent
```

建议从以下方向判断是否需要：

### 1. 学习状态管理

- 当前学习阶段
- 已学习知识
- 未掌握知识
- 最近错误
- 最近训练情况

### 2. 个性化训练路径

例如：

```text
C++基础
复杂度
STL
基础算法
数据结构
图论
DP
数学
```

AI 不应该机械固定路线，而应该根据用户状态调整。

### 3. 个性化题目推荐

根据：

```text
知识点
难度
历史正确率
最近错误
训练目标
```

推荐题目。

### 4. Progressive Hint

不要直接给完整答案。

例如：

```text
Hint 1：提醒观察
Hint 2：指出知识方向
Hint 3：给关键性质
Hint 4：给伪代码
Hint 5：必要时才给完整解析
```

### 5. Debug Agent

处理：

```text
CE
WA
TLE
RE
MLE
```

但尽量通过引导让用户自己发现问题。

### 6. 知识点讲解

根据学生真实水平调整讲解深度。

### 7. 错题与薄弱点管理

自动记录：

```text
不会的题
错误类型
知识漏洞
反复错误
```

### 8. 自动复习

类似：

```text
今天
3天后
7天后
21天后
```

重新安排相关知识或题目。

### 9. 训练复盘

每天/每周告诉学生：

```text
做了什么
掌握了什么
哪里薄弱
下一步做什么
```

2. 数据不支持的结论明确标记为假设。
3. 样本不足时明确说明。
4. 区分相关关系与因果关系。
5. 不因为某个功能选择人数多就直接判断一定应该开发。
6. 优先寻找真正高频、高痛点、可解决的问题。
7. 产品建议优先考虑：
   - 小团队
   - 低成本
   - 快速开发
   - 快速验证
8. 不要一开始规划复杂微服务。
9. 不要建议自研大模型。
10. 可以优先利用成熟 LLM API。
11. 当前最重要的是验证“是否真正帮助训练”，而不是做很多功能。
12. 最终产品规划必须能够落地，而不是只写概念。
